Design decisions

Decision Rationale Tradeoff Evidence
Exit/reconcile existing trades before new entries. Preserves trade slots and avoids order/force-exit races using exit lock. Order/analysis latency is tied to serial loop processing and configured refresh cadence. FreqtradeBot.process (L306)
Separate vectorized signal preparation from chronological trade simulation. DataFrame hooks compute indicators efficiently while order/portfolio path remains stateful. Vectorized indicators do not establish a fully vectorized fill/portfolio engine. IStrategy.populate_entry_trend (L254) / Backtesting.backtest (L1763)

Workflow

Live/dry-run processing cycle

Live/dry-run routing is controlled by Exchange.create_order; none of these network operations were executed during this audit.

Diagram source

  W1["Refresh tradeable and informative candles."]
  W0 --> W1
  W2["Run strategy loop callback and analyze pair DataFrames."]
  W1 --> W2
  W3["Manage open orders, exit existing trades and adjust positions first."]
  W2 --> W3
  W4["Enter new positions if running with free slots."]
  W3 --> W4
  W5["Commit persistent state and dispatch RPC messages."]
  W4 --> W5

  5. Enter new positions if running with free slots.. FreqtradeBot.process (L306)

Strengths and limits

Strengths

  • The live/dry-run loop preserves shared strategy hooks and reconciliation order, while historical trials reuse the chronological backtesting engine. FreqtradeBot.process (L306) / Exchange.create_dry_run_order (L1206) / Backtesting.backtest (L1763) / Hyperopt.start (L216)

Limitations

  • Each bot instance owns one exchange; multi-venue selection should not be described as simultaneous cross-venue execution within that instance. FreqtradeBot.init (L94)
